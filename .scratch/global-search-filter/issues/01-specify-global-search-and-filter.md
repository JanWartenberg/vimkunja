## Agent Brief

**Category:** enhancement
**Summary:** Add a live, full-database global Search overlay and reusable label-filtered Overview scope.

**Current behavior:**
Vimkunja has no global search. Overview’s `f` command narrows only its loaded Task list by status, and the Task editor’s Project picker filters only its own Project choices. There is no typed search result, search-return state, Label discovery, or label-filtered Overview scope.

**Desired behavior:**
`Space+f` opens a modal global Search overlay above the current context; `/` remains reserved for future local search. The overlay queries the complete locally browsable SQLite data set, independent of loaded Pane pages or the current Project/View, while retaining normal archive visibility rules. It searches and displays plain text only: never raw Description HTML.

Queries update live. A blank query shows guidance rather than every record. Matching is case-insensitive substring matching: split whitespace-separated terms and require every term to occur in the same result kind’s searchable text. Do not implement quoted phrases, negation, fuzzy matching, or cross-kind/field matching in V1.

Render nonempty groups in this order: Tasks, Labels, Descriptions, Projects. Rows within a group sort alphabetically by their primary visible text, then ID. Tasks are title matches; Labels are Label rows only; Descriptions are Task rows whose Description text matches and show Task title, Project context, and a bounded wrapping plain-text excerpt around the first match; Projects match title or identifier. Highlight every visible matching span.

`Enter` activates the selected result: a Task or Description opens the owning Project’s List View with that Task selected in the Task Detail Pane; a Project enters its List View; a Label opens a reusable label-filtered Overview scope. That scope lists Tasks carrying the Label and composes with the existing Overview status filter, initially `open`; its header exposes both constraints. The global Search must provide the read-only Label and Task-query capability needed for this navigation, but does not add Label mutation UI.

While the input accepts text, arrow keys and `Ctrl+N`/`Ctrl+P` select results. `n/N` remain reserved for future local-search repeat behavior. `Esc` closes the overlay and restores the exact pre-search context. After result activation, `Ctrl+O` returns to the latest session-local Search snapshot, restoring its query, result set, selected row, and scroll position; `Esc` from that restored overlay returns to the original context. Respect existing unsaved-edit protection.

Keep the overlay open on empty results or an unexpected search error, with clearly distinct states. Retain the query and last valid results on error, and discard asynchronous responses that no longer match the current query.

**Key interfaces:**
- A typed Search-result model — identifies Task, Label, Description, and Project result rows; carries activation identity and safe presentation context without leaking source HTML.
- A Search-query module — owns full-data lookup, normalization, matching, grouping, ordering, snippets, and stale-result protection behind one interface.
- A Task-query module — supplies the label-filtered Overview collection independently of the Search overlay, so the Labels feature can reuse it.
- Search-overlay and Overview state — preserve origin/return snapshots, route typed result activation, and compose Label and status constraints.

**Acceptance criteria:**
- [ ] `Space+f` opens a live global Search overlay over every eligible normal context; blank query, no-result, and unexpected-error states are distinct and `Esc` restores the origin.
- [ ] Search consults the complete locally browsable data set rather than only loaded pages, respects ordinary archive visibility, and exposes no raw HTML.
- [ ] Matching, groups, group order, row ordering, and visible match highlighting follow the specified V1 contract.
- [ ] Description hits show Task and Project context plus a bounded wrapping plain-text excerpt around the match.
- [ ] Task/Description, Project, and Label activation perform their specified navigation; a Label opens an `open` label-filtered Overview and its status filter continues to compose normally.
- [ ] Arrow keys and `Ctrl+N/P` navigate picker rows without preventing text entry; `n/N` have no global-search behavior.
- [ ] `Ctrl+O` restores the latest Search snapshot after activation, including query, selection, and viewport; unsaved edits still block unsafe navigation.
- [ ] Stale search responses cannot replace newer-query results; error responses retain the latest valid results and query.
- [ ] Store/query and model-level tests cover each result kind, multi-term matching, empty/error/stale responses, Label scope composition, activation, and search return.

**Out of scope:**
- Future local `/` search and its `n/N` repeat behavior.
- Quoted phrases, negation, fuzzy/typo-tolerant search, or relevance ranking.
- Label creation, assignment, removal, editing, or deletion; those belong to the Labels feature.
- Persistent search history, a general jump list, or `Ctrl+I` forward navigation.
- Projects-Pane filtering and changes to the Vikunja schema.

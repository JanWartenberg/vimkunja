## Agent Brief

**Category:** enhancement
**Summary:** Render and navigate the persisted Vikunja Project hierarchy in the Projects Pane, including session-local folding and sibling reordering.

**Current behavior:**
Projects are read and rendered as a flat, ID-ordered list. The read model does not carry parent or position information. Refresh retains a row index rather than a selected Project identity, and the Pane has no independent viewport or tree behavior.

**Desired behavior:**
Read the existing Project parent relationship and position without changing the Vikunja schema. Normalize a null or zero parent as a root. Build a defensive, testable hierarchy whose roots and each sibling group sort by position ascending then ID ascending. Fetch the complete active Project set before building the tree.

Render the visible flattened tree in the Projects Pane with two spaces per depth, a fixed-width `▾` open-branch / `▸` closed-branch marker, and an aligned blank leaf marker. The selected Project retains its indentation and is color-highlighted as `> Project <`; do not render `[X]`. The Pane owns a vertical viewport, and `j/k`, `gg/G`, and `Ctrl+D/U` navigate visible tree rows while keeping selection visible.

All branches start expanded on a fresh launch. Fold state is session-local and retained by Project ID across refreshes; a newly observed branch starts expanded. Support `zo`, `zc`, `za`, `zM`, and `zR`. Also support tree navigation: `l` opens a closed branch or selects an already-open branch's first child; `h` closes an open branch or, for a closed branch/leaf, selects its parent.

`Shift+J` and `Shift+K` move the selected Project one position among only its siblings. A moved parent carries its entire subtree and all descendant fold states. Persist the reorder transactionally without changing parent relationships. Do not optimistically redraw: retain the prior display on write failure and use normal error feedback; on success reload/rebuild and retain selection by ID.

Every loaded Project must render exactly once. A negative, missing, self, or cyclic parent relationship must not recurse indefinitely or hide data: render affected Projects as `!`-marked root-level recovery entries after valid roots.

Refresh retains selection by Project ID and expands ancestor branches necessary to reveal it. If the selected Project no longer exists, select the next former-position visible row, then the preceding row, or show the empty state if none remain.

**Key interfaces:**
- `vimkunja.Project` and Project-loading Store operations — expose normalized parent identity and persisted position; retrieve all active Projects; add a transactional sibling-reordering operation.
- A hierarchy builder / visible-row projection — encapsulates ordering, malformed-data recovery, folding, and visible-row navigation independently of terminal rendering.
- The Projects-Pane model and key handling — keep selection by Project ID, own the viewport, execute folding/tree navigation, and delegate persistence to the Store.

**Acceptance criteria:**
- [ ] A multi-level valid hierarchy renders in position/ID sibling order with the specified indentation, branch markers, selected-row presentation, and viewport behavior.
- [ ] All fold commands and `h/l` follow the specified behavior; fold state survives refresh in a session but not restart.
- [ ] Navigation commands operate only over visible rows, and refresh preserves/reveals the selected Project or uses the defined disappearance fallback.
- [ ] `Shift+J/K` only reorder siblings, retain a parent subtree, persist compatible positions transactionally, and leave the display unchanged on write failure.
- [ ] Null/zero parents are roots; missing, negative, self-referential, and cyclic inputs terminate safely and appear once as marked recovery roots.
- [ ] Store and model tests cover valid nesting, ordering ties, folding/navigation, refresh selection, disappearance, malformed data, and sibling reordering.
- [ ] No Vikunja schema change is made.

**Out of scope:**
- Filtering the Projects Pane; the global-search/filter ticket owns that contract.
- Persisting fold state across application restarts.
- Changing a Project's parent or moving it across sibling groups.
- A footer diagnostic or repair workflow for malformed hierarchy data; that is a future low-priority ticket.
- The shared visual scrollbar/percentage affordance, which belongs to the scroll-position-feedback ticket.
